# Build Log — FrankenMCP

How this project was built with Kiro, session by session. Dates are Asia/Dhaka.
This log is the source for the Kiro write-up in the Devpost submission.

## Nov 15 — Phase 0: concept + spec

- Picked the Frankenstein category and the FrankenMCP concept: give any CLI
  tool a second life as an MCP server, and show exactly what it costs the
  context window. The idea comes from my own measurement work — 68 MCP tools
  cost 23,300 context tokens, and trimming them to names-only cut that to 485.
- Wrote the spec first, in Kiro: 9 requirements (EARS format), a design doc,
  and a 33-task plan in `.kiro/specs/frankenmcp/`, plus steering docs
  (product / tech / structure) and hooks (lint + test on save). The spec is
  the source of truth; code follows it, and when code and spec disagree the
  spec gets updated deliberately.
- Created the public repo `marketersalam-ux/frankenmcp` (MIT) and committed
  `.kiro/` first, so the Kiro evidence is at the root from the first commit.

## Nov 15 — Phases 1–3: core engine (Kiro CLI)

Built with Kiro CLI sessions against the spec, one module per session, each
verified by its own tests before moving on. Models used: qwen3-coder-next
for the first session, then claude-haiku-4.5 for the rest — the cheaper model
thrashed on the parser (hardcoded tool names, duplicated blocks), and the
stronger model finished each module in one clean pass.

- **Help parser** — parses GNU-style `--help` text into flags, subcommands
  and unparsed lines. Verified against real help output: ffmpeg 43 flags,
  git 22 subcommands, curl 256 flags. A 200-run property test (fast-check)
  round-trips model → rendered help → parse → equal.
- **Tokens** — real token counts with tiktoken `cl100k_base`, per tool and
  total, plus a trimmed-config builder (full / trimmed / names-only).
- **Safety** — deterministic rules flag destructive options, path flags and
  network/credential flags. Matching is whole-word + phrase rules, after
  substring matching falsely flagged `--form`, `--hardware` and `--support`.
- **Adapter generator** — turns a parsed CLI model into a working MCP server
  (`server.js` + `package.json` + README + tool schemas), with schema
  validation. One `callTool` + command/flag maps, so multi-tool servers work.
- **Agent loop** — a deterministic loop (parse → generate → validate → fix →
  verify) with a visible step log. Files are always rebuilt from fixed tools,
  so the download and the tool list can never diverge.
- **Dogfood servers** — a bundled demo CLI (textkit: wc/reverse/slugify/upper)
  whose MCP server was generated by our own generator, plus a calculator
  server. The dogfood test compares live MCP calls against direct CLI output.
- **MCP client + API routes** — stdio for the bundled allowlist, SSE and
  streamable-HTTP for remote URLs, with timeouts, caps and an SSRF blocklist.
  Three API routes: `/api/generate`, `/api/connect`, `/api/probe`.
- **End-to-end proof** — generated an adapter for a tiny test CLI and drove
  it with a real MCP client: `listTools` returned the tool, `callTool`
  produced exactly the expected argv, and an unknown argument returned a
  proper error. The core claim — "generates working MCP servers" — is
  verified end to end, not just unit-tested.

Review notes (the honest part): review caught real bugs along the way and
they were fixed before moving on — a per-tool `callTool` that shadowed
itself, a fix path that rebuilt files from unfixed tools, an arg parser
that only read leading flags, and an SSRF gap where bracketed IPv6 hosts
slipped past the `::1` check. Nothing was left known-broken.

## Nov 15 — Phase 4: UI (Kiro CLI, 3 batched sessions)

- **Generate panel** — paste `--help` text or pick a sample, watch the agent
  log, see per-tool costs, read the safety review, download the verified
  `.zip` (server code + `COSTS.md` receipt + `SAFETY.md`).
- **Connect panel** — pick a bundled server or a remote URL, see the live
  tool list with real tiktoken costs, probe tools with a schema-driven form.
  Review caught a real bug here: the cost table was showing a chars/4
  client-side estimate under a footnote claiming `cl100k_base`. It now uses
  the real costs from `/api/connect`. No number in the UI is estimated by
  arithmetic — every count comes from the tokenizer.
- **Config panel** — build a trimmed config (full / trimmed / names-only)
  and copy or download it, with the token saving shown.
- **Verification** — 212/212 tests pass (19 files), `tsc`, ESLint and
  Prettier clean, production build succeeds. End-to-end run against a local
  dev server: generate ffmpeg → connect textkit → probe slugify →
  trim names-only (saved 211 tokens). No sign-in, no API key anywhere.
